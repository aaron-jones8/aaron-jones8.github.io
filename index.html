Professional Self-Assessment

Introduction

Completing the Computer Science program at Southern New Hampshire University, and this capstone in particular, has given me a clearer picture of what I can actually do rather than just what I've been taught. I haven't committed to a narrow specialization within computer science, and at this point in a genuinely competitive field — one being reshaped by AI as quickly as it is — I'm not trying to brand myself around one. What I want this portfolio to demonstrate is more fundamental than that: that I'm capable, that I can take on a task I haven't necessarily done before, and that I can see it through to something that actually works. The three artifacts in this portfolio, each enhanced in a different core area of computer science, are the clearest evidence I have of that.

Collaborating in a Team Environment

Most of my coursework has been independent, structured project work, so the clearest example I can point to of working within a shared, collaborative environment is the structured peer-review process built into courses like CS 465 (Full Stack Development), where I wrote discussion posts and peer responses to classmates' work. That format is asynchronous and lower-stakes than a shared codebase, and I want to be honest about that rather than overstate it, but it's still a real exercise in the skill underneath real teamwork: reading someone else's technical decisions, understanding the reasoning behind them, and giving feedback that's useful rather than just correct.

Communicating with Stakeholders

Two of the artifacts in this portfolio were built directly around a specific audience's stated needs rather than an abstract specification. The Contact/Task/Appointment management services were built for a named fictional client, Grand Strand Systems, which meant translating plain-language client requirements into concrete validation rules and automated tests. The Grazioso Salvare Rescue Animal Dashboard was built around a real rescue organization's actual workflow, which meant the technical design had to disappear behind an interface a non-technical stakeholder could just use. Outside this portfolio, my MAT 350 (Applied Linear Algebra) discussion posts required explaining results like singular value decomposition and image compression in plain language for a reader without the same math background.

Data Structures and Algorithms

The clearest demonstration of this in the portfolio is the Milestone Three enhancement to the ABCU Advising Program, replacing a vector-based linear search with a hash map and turning the program's most frequent operation from an O(n) scan into an O(1) average-case lookup. Outside this portfolio, my strongest algorithms work was in CS 370 (Artificial Intelligence), where I built a reinforcement-learning agent — implementing Q-learning, A2C, and REINFORCE — that reached a 100% win rate on its task.

Software Engineering and Database

This is the area where this portfolio's artifacts carry the most direct weight. The Milestone Two enhancement introduced a repository interface and a file-backed persistence layer in front of services that had been directly coupled to an in-memory map, with integration tests, a Maven build, and a GitHub Actions CI workflow to support it. The Milestone Four enhancement completed a CRUD module that had never implemented update or delete, and added a compound index built around the dashboard's own query patterns. Outside the portfolio, I maintain a self-hosted home server running a Docker-based stack with its own backend scripting and API work.

Security

The Milestone Four enhancement is this portfolio's direct evidence of a security mindset: removing hardcoded database credentials, fixing a connection check that silently accepted bad credentials, escaping credentials before they're placed in a connection URI, and adding guardrails against an accidental mass update or delete. Outside the portfolio, CS 370's AI ethics work, including a white paper on GDPR, pushed me to think about privacy and data protection from a policy and design angle as well as a code-level one.

How the Artifacts Fit Together

The three artifacts were chosen to cover three different, necessary layers of the same kind of work: sound object-oriented design and disciplined testing; recognizing and fixing a real data-structure trade-off; and taking a full application — database, backend logic, and a usable front end — and making it both more complete and more secure. None of them were already finished, polished projects before this course; each had a real, identifiable problem that I diagnosed and fixed, which is closer to what maintaining software in a job actually looks like. Taken together, given an existing system and a real problem in it, I can figure out what's actually wrong, fix it correctly, and prove that the fix works.

Milestone Two · Category One

Software Design and Engineering

Contact/Task/Appointment Management Services — a set of Java entity and service classes originally built for CS 320: Software Testing, Automation, and Quality Assurance, with validated, immutable-ID entities and a JUnit test suite.

What changed

  • Introduced a repository interface for each entity, so the services depend on an abstraction instead of a concrete in-memory map.
  • Added a file-backed repository implementation alongside the original in-memory one, so data now persists across restarts — and made real integration tests possible for the first time.
  • Fixed an invalid-regex bug in phone validation, added missing existence checks on update methods, and standardized on JUnit 5.
  • Consolidated three separate Eclipse projects into one Maven project with a GitHub Actions CI workflow that runs the full suite on every push.

Milestone Three · Category Two

Algorithms and Data Structures

ABCU Advising Program — a C++ console application originally built for CS 300: Data Structures and Algorithms, comparing a vector, a hash table, and a binary search tree for the same course-advising task.

What changed

  • Replaced the vector-based linear search with an unordered_map keyed by course number — turning the program's most frequent operation from an O(n) scan into an O(1) average-case lookup.
  • Fixed a Windows-line-ending (CRLF) bug that was silently corrupting the last field of every data row.
  • Added real error handling for a file that fails to open, and validation that skips and reports malformed data rows.
  • Fixed an infinite-loop bug triggered by non-numeric menu input.

Milestone Four · Category Three

Databases

Grazioso Salvare Rescue Animal Dashboard — a Python, PyMongo, and Dash application originally built for CS 340: Client/Server Development, filtering real Austin Animal Center shelter data by rescue-type profile.

What changed

  • Removed hardcoded database credentials in favor of environment variables, with a clear error if they're missing.
  • Completed the CRUD module — the original never implemented update() or delete() — with safeguards against an accidental mass update or delete on an empty query.
  • Added a compound index on the exact fields the dashboard's filters query together, following equality-then-range ordering.
  • Fixed a connection check that silently accepted bad credentials, escaped credentials in the connection URI, and added error handling for a missing logo file.
